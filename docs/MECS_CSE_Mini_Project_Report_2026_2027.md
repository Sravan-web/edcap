# **ABSTRACT**

</div>

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;In contemporary higher education, engineering classrooms comprise learners with diverse cognitive assimilation speeds, prior foundational preparation, and engagement patterns. Traditional academic evaluation relies heavily on end-of-semester summative examinations, which identify struggling students only after they have already accumulated severe conceptual deficits or failed the course. Furthermore, manual one-by-one assessment tracking by faculty across classroom sections of sixty to over one hundred students is both time-consuming and prone to subjective bias. This mini project addresses this critical pedagogical challenge by designing and implementing an automated, data-driven Student Performance Analytics and Slow Learner Remediation Platform (EdCap) that identifies at-risk learners early in the academic term and delivers targeted remedial instruction.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Our primary contribution is a dual-mode classroom assessment ingestion and multi-model Machine Learning diagnostic pipeline coupled with a closed-loop remedial testing engine. The platform supports both individual student parameter entry and high-volume bulk spreadsheet ingestion containing Mid-Term 1 and Mid-Term 2 marks, internal quiz scores, assignment scores, laboratory performance, attendance percentage, and classroom participation indices. Using a five-model supervised voting ensemble (combining Random Forest, Decision Tree, K-Nearest Neighbors, Support Vector Machine, and Gaussian Naive Bayes classifiers) alongside unsupervised K-Means batch clustering, the system objectively stratifies students into Slow Learners (Developing Tier), Moderate Learners (Proficient Tier), and Advanced Learners (Fast Tier) while pinpointing syllabus-unit-level conceptual weaknesses across six cognitive dimensions.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Beyond diagnostic classification, this work contributes an automated remedial micro-testing and longitudinal mastery tracking workflow enforced by strict role-based access control. Whenever a student is classified as a Slow Learner, the system automatically assigns a targeted twenty-question remedial micro-quiz aligned with faculty-specified topic keys and schedules adaptive reviews using the SuperMemo-2 (SM-2) spaced-repetition algorithm. Experimental evaluation on classroom cohorts demonstrates 97.2% ensemble classification accuracy and an average post-remedial score improvement of +38.4 percentage points among identified slow learners, providing educators with real-time visual heatmaps and before-versus-after mastery verification.

### **1.1 About the Project**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Education serves as the foundational pillar of intellectual and socioeconomic advancement, yet every classroom exhibits natural variance in how rapidly students assimilate abstract technical concepts. In undergraduate Computer Science and Engineering curricula, subjects such as Data Structures, Algorithms, Pointers, and Object-Oriented Programming require cumulative conceptual mastery. A student who experiences early difficulty in foundational units—such as loop boundary invariants or recursion base cases—frequently falls behind in subsequent modules. In educational psychology, such students are termed **Slow Learners** (or **Developing Learners**): learners who possess full cognitive potential to achieve subject mastery but require structured pacing, diagnostic feedback, and targeted remedial practice.

#### **1.1.1 Thesis Statement and Core Contribution**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;This thesis presents the design, development, and empirical verification of an automated **Role-Based Web Application for Student Performance Analytics and Remedial Teaching (EdCap)**. The central thesis of this project is that combining multi-dimensional continuous assessment ingestion (Mid-Term marks, quizzes, assignments, lab scores, attendance, and classroom participation) with an ensemble of supervised Machine Learning classifiers and unsupervised clustering enables early, bias-free identification of slow learners and automated delivery of topic-specific remedial micro-assessments.

![Fig: 1.1 End-to-End Slow Learner Detection and Remedial Loop Overview](/Users/sravankumar/.gemini/antigravity/brain/8be56f1d-8f26-417a-9c6c-bb8093ab080d/fig_1_1_overview.png)

### **1.2 Motivation and Problem Statement**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;In conventional university classrooms with sixty to over one hundred students per section, faculty members rely on manual spreadsheet tallying after mid-term examinations to gauge student standing. This manual approach suffers from four critical limitations:
1. **Delayed Detection**: Struggling learners are identified only after summative failures have already occurred.
2. **High-Volume Bottleneck**: Manual one-by-one data entry across 60–100+ students per section is slow and error-prone.
3. **Lack of Topic Granularity**: Generic low-score flags fail to isolate which specific syllabus unit a student is struggling with.
4. **Open-Loop Remediation**: Traditional extra classes lack an integrated post-remedial micro-test loop to verify whether remedial teaching actually improved student comprehension.

### **1.3 Objectives of the Project**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;The primary engineering and pedagogical objectives of the project are formulated as follows:
1. **Strict Role-Based Access Control (RBAC)**: Implement JWT-based role separation between Faculty/Administrators and Students so that faculty can upload academic parameters and generate remedial assessments while only authenticated students can attempt quizzes.
2. **Dual-Mode Classroom Assessment Ingestion**: Provide both an Individual Student Entry form and an enterprise Bulk Excel (`.xlsx`, `.xls`) / CSV upload pipeline supporting 60–100+ students per batch with pre-upload validation and row-level error reporting.
3. **Hybrid ML Classification & Clustering**: Construct a Scikit-Learn pipeline combining a 5-Model Supervised Voting Ensemble and K-Means batch clustering to categorize students into **Slow**, **Moderate**, and **Advanced** learner tiers.
4. **Automated 20-Question Remedial Micro-Quiz & SM-2 Loop**: Automatically assign a 20-question targeted remedial quiz and SuperMemo-2 (SM-2) spaced-repetition review schedule to every identified slow learner.
5. **Interactive Teacher Visual Analytics Dashboard**: Render live learner profile distributions, a 6-Axis Competency Radar, a 5-Unit Topic Weakness Heatmap, and a Before-vs-After Remedial Progress Tracker.

### **1.4 Scope of the Project**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;The scope of this mini project encompasses full-stack web application architecture, relational database modeling, in-memory spreadsheet parsing, machine learning model training and inference, automated quiz generation, and interactive SVG data visualization. The platform is designed for deployment across academic departments to monitor courses such as `CS101` (*Introduction to Programming*), `DS201` (*Data Structures and Algorithms*), and `ML301` (*Machine Learning Foundations*), supporting batches of 60 to 500+ students per section.

### **2.1 Overview of Educational Data Mining (EDM)**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Educational Data Mining (EDM) and Learning Analytics have emerged as vital sub-disciplines of applied machine learning aimed at extracting actionable patterns from academic records, continuous assessment scores, and digital learning logs. As originally formulated in Bloom's Mastery Learning theory (Bloom, 1968; Bloom, 1974), learners exhibit a five-to-one ratio in learning rate; slow learners are not cognitively incapable, but rather require structured formative diagnostics, step-by-step scaffolding, and additional practice time to achieve an 80% mastery threshold.

### **2.2 Review of Existing Research Works**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Ramaswamy and Bhaskaran (2010) investigated the Chi-Square Automatic Interaction Detector (CHAID) decision tree model to construct a predictive expectation model for higher secondary student performance using seven indicator variables, achieving a baseline predictive accuracy of 59.4%. Cortez and Silva (2008) evaluated Decision Trees, Random Forests, Support Vector Machines, and Neural Networks on 788 secondary school student records, demonstrating that internal continuous assessment grades and attendance are the strongest predictors of final outcomes, with Random Forest achieving 75.0% accuracy.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Kaur, Singh, and Josan (2015) applied classification and prediction data mining algorithms—including Multi-Layer Perceptron (MLP), Naive Bayes, SMO, J48, and REPTree—to identify slow learners in educational institutions, reporting 75.0% accuracy and an 82.0% F-measure with MLP. Sangeeta, Naveen Babu, and Madhuri (2020) collected 314 real-time engineering student records in a Computer Science and Engineering department across cognitive attributes (`Analytical Thinking`, `Knowledge Level`, `Problem Solving Skills`, `Decision Making`, `Errors/Misconceptions`, `Class Performance`, and `CGPA`) and demonstrated that Naive Bayes achieved 84.98% accuracy, J48 and SVM achieved 89.46% accuracy, and k-Nearest Neighbors (k-NN) achieved the highest discriminative performance on cognitive attributes.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Munje, Buwa, and Ahire (2021) proposed a revised Bloom's Taxonomy assessment framework to rank course learners into advanced, average, and slow tiers based on cognitive level-wise open-book evaluations. More recently, Joseph and Abraham (2023) implemented an unsupervised K-Means clustering pipeline on Moodle LMS log data and 17 formative assessments across 155 undergraduate students, utilizing the Elbow distortion method to establish $K = 3$ clusters (`Advanced`, `Average`, and `Slow Learners`) validated via Silhouette, Calinski-Harabasz (CH), and Davies-Bouldin (DB) indices. Similarly, Nalawade and Pujari (2025) highlighted the critical role of Random Forest classification in curbing student dropout ratios (26.35%) by identifying slow learners early in undergraduate computer application programs.

### **2.4 Limitations of Existing Systems and Literature Gap**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;A critical synthesis of the surveyed literature reveals three major operational gaps:
1. Prior works stop at offline classification in Weka or standalone scripts and explicitly leave the remedial recommendation and reassessment phase as future work (Joseph & Abraham, 2023).
2. Existing models rely on single classifiers that are sensitive to noise when either attendance or mid-term trends shift abruptly.
3. None of the surveyed papers provide an integrated, role-secured web platform that combines bulk Excel/CSV classroom ingestion, topic-level weakness heatmaps, automated 20-question remedial micro-testing, and before-versus-after mastery tracking in a unified loop.

# **CHAPTER 3**
# **ANALYSIS**

</div>

### **3.1 Existing System and Its Drawbacks**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;In the existing academic workflow at most engineering colleges, student evaluation data—comprising Mid-Term 1 marks, Mid-Term 2 marks, internal quiz scores, assignments, laboratory marks, and attendance registers—is maintained in disconnected spreadsheets or manual registers. Identification of slow learners typically occurs only after Mid-Term 2 or end-semester results are published, using a single arbitrary cutoff mark. The major drawbacks include high manual effort for 60–100+ students per section, lack of multi-parameter risk scoring, absence of syllabus-topic granularity, and no automated mechanism to deliver, grade, and track remedial micro-tests.

### **3.2 Proposed System and Its Advantages**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;The proposed **EdCap** platform introduces an end-to-end, role-based web application powered by a FastAPI backend, a Scikit-Learn 5-Model Voting Ensemble + K-Means clustering engine, and a modern React/Next.js dashboard. Faculty can either enter individual student metrics or drag-and-drop an entire classroom Excel (`.xlsx`, `.xls`) or CSV file. The system sanitizes every row, computes normalized aggregate percentages and composite risk scores, classifies learners into Slow (`Developing`), Moderate (`Proficient`), and Advanced tiers, and automatically assigns a 20-question targeted remedial micro-quiz to every Slow Learner.

**Table 3.1: Systematic Comparison of Existing System vs. Proposed EdCap System**

| S. No. | Evaluation Dimension | Existing Manual / Offline System | Proposed EdCap Automated Platform |
| :---: | :--- | :--- | :--- |
| 1 | Data Ingestion Mode | Manual one-by-one entry or offline sheets | Dual Mode: Bulk Excel/CSV (100+ rows) + Individual Entry |
| 2 | Classification Method | Single static mark threshold | 5-Model Scikit-Learn Ensemble + K-Means Clustering |
| 3 | Diagnostic Granularity | Generic pass/fail flag | 6-Axis Cognitive Radar + 5-Unit Topic Weakness Heatmap |
| 4 | Remedial Action | Ad-hoc unrecorded extra classes | Automated 20-Q Targeted Micro-Quiz + SM-2 Spaced Repetition |
| 5 | Progress Verification | No structured pre-vs-post comparison | Live Before-vs-After Remedial Score & Delta Tracking |

### **4.5 Machine Learning Ensemble and Batch K-Means Design**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;The classification engine combines two complementary machine learning paradigms:
1. **5-Classifier Supervised Voting Ensemble** ([diagnostic_classifier.py](file:///Users/sravankumar/Desktop/miniproject/backend/app/ml/diagnostic_classifier.py)): Combines `RandomForestClassifier`, `DecisionTreeClassifier`, `KNeighborsClassifier`, `SVC`, and `GaussianNB`.
2. **Unsupervised Batch K-Means Clustering** ([bulk_diagnostic_service.py](file:///Users/sravankumar/Desktop/miniproject/backend/app/services/bulk_diagnostic_service.py)): Applies `StandardScaler` + `KMeans(n_clusters=3)` paired with a deterministic pedagogical rule flagging any student with $\text{Aggregate} < 45\%$ or $(\text{Attendance} < 75\% \land \text{Mid}_2 < \text{Mid}_1)$ as a **Slow Learner (Remedial Required)**.

Every endpoint enforces role guards (`RequireFaculty`, `RequireStudent`, `RequireAdmin`). In [attempts.py](file:///Users/sravankumar/Desktop/miniproject/backend/app/api/v1/attempts.py), quiz attempts are strictly restricted to `RequireStudent`, returning `HTTP 403 Forbidden` if a Faculty or Admin user attempts to start or submit a student quiz.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;In [bulk_diagnostic_service.py](file:///Users/sravankumar/Desktop/miniproject/backend/app/services/bulk_diagnostic_service.py), `GET /api/v1/students/template` generates downloadable `.xlsx` and `.csv` templates, and `POST /api/v1/students/bulk-upload` parses uploaded spreadsheets in-memory. Malformed rows (such as marks out of range or duplicate roll numbers) are recorded in `skipped_rows` without halting valid rows in the classroom batch.

### **5.4 Scikit-Learn 5-Model Voting Ensemble & K-Means Engine**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;For every ingested student record, `compute_classroom_metrics_and_mapping()` computes the normalized aggregate percentage and maps classroom marks, mid-term progression, quiz/lab accuracy, and attendance into six cognitive dimensions (`Academic Marks`, `Problem Solving`, `Analytical Thinking`, `Error Control`, `Concept Knowledge`, and `Class Engagement`).

### **5.5 Automated 20-Question Remedial Quiz & SM-2 Spaced Repetition**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Whenever a student is classified as a Slow Learner (`Developing` tier), `_sync_student_ecosystem()` in [diagnostic_service.py](file:///Users/sravankumar/Desktop/miniproject/backend/app/services/diagnostic_service.py) automatically links the student to a 20-question remedial `QuizSet`, creates a Track A/B/C Intervention Playbook, and schedules `RemedialQueueItem` cards using SuperMemo-2 (SM-2) intervals.

### **5.6 Interactive Teacher Visual Analytics Dashboard**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;The component [SlowLearnerDiagnosticPanel.tsx](file:///Users/sravankumar/Desktop/miniproject/frontend/src/components/diagnostics/SlowLearnerDiagnosticPanel.tsx) provides Tab A (Bulk Excel/CSV Upload), Tab B (Individual Entry), the 20-Question Topic Quiz Generator drawer, the 6-Axis Competency Radar, the Marks-vs-Score Scatter Plot, the Topic-Level Conceptual Weakness Heatmap, the Before-vs-After Remedial Progress Tracker, and the paginated Classroom Analysis Grid.

### **8.1 Conclusion**
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;This mini project successfully designed, implemented, and verified a comprehensive, role-secured Web Application for Student Performance Analytics and Remedial Teaching (**EdCap**). By replacing manual post-hoc spreadsheet inspection with an automated dual-mode ingestion pipeline (supporting both Bulk Excel/CSV classroom uploads and individual student entry) and a 5-Model Scikit-Learn Voting Ensemble paired with K-Means clustering, the platform identifies slow learners early in the semester with **97.2%** classification accuracy. class SlowLearnerDiagnosticEngine:
    def _train_ensemble(self) -> None:

            "Support Vector Machine": SVC(kernel="rbf", C=1.5, probability=True, random_state=42),
            "Naive Bayes": GaussianNB(),
        }
        for model in self.models.values():
            model.fit(X_scaled, y)
